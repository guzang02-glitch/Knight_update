## 1. 개요

### 1.1 설계 목표

| 목표 | 내용 |
|---|---|
| 초반부터 상승 | 1스테이지부터 경우의 수 목표 곡선 추종, 4×4 구간 스테이지당 약 1.3배 |
| 리듬 있는 50스테이지 | 5의 배수 관문(갈림길 많음) · 끝자리 3 · 8 먼 길(칸 많음) |
| 정답 1개 · 재현성 | 모든 스테이지 정답 경로 1개 검증, 선택 시드 고정 |

### 1.2 난이도 지표 정의

| 지표 | 정의 |
|---|---|
| LEN | 시작 칸부터 성까지 밟아야 하는 칸 수 (시작 · 성 포함) |
| 경우의 수 | 시작 칸에서 만들 수 있는 이동 순서의 총수 (막힐 때까지의 모든 갈래 포함), 40만 초과 시 표본 추정 |

## 3. 제작 프로세스

### 3.1 레벨 제작 흐름

1. 후보 맵 생성 — LEN별 시드 120개, 정답 경로 선생성 · 나머지 칸 바위
2. 정답 수 · 경우의 수 측정 — 정답 경로 1개인 맵만 통과, 이동 순서 총수 측정
3. 맵 선택 · 고정 — 일반 → 먼 길 → 관문 순 선택, 선택 시드 StageTable 고정

### 3.2 규칙 검사

| 검사 항목 | 조건 | 결과 |
|---|---|---|
| 일반 증가 | 직전 일반 스테이지보다 경우의 수 증가 | 통과 (29/29) |
| 먼 길 LEN | 앞뒤 일반 스테이지보다 LEN 김 | 통과 (10/10) |
| 먼 길 경우의 수 | 앞뒤 일반 스테이지보다 경우의 수 적음 | 통과 (10/10) |
| 관문 경우의 수 | 같은 구간 앞 스테이지 · 다음 스테이지보다 많음 | 통과 (10/10) |
| 정답 1개 | 모든 스테이지 정답 경로 정확히 1개 | 통과 (50/50) |
| 힌트 완주 | 막힘 상태에서 힌트만으로 성 도착 (스테이지당 15판) | 통과 (750/750) |

## 6. 부록

### 6.1 검증 결과

규칙 검사 50/50 · 힌트 완주 750/750 · 정답 1개 스테이지 50/50 · 힌트 계산 최대 2ms

### 6.2 미결 사항

- [ ] 체감 난이도 검증 — 경우의 수와 실제 클리어율 · 시간 상관 확인
- [ ] 4×4 구간 한계 — 칸 16개, 단일 해 기준 경우의 수 최대 약 130가지
- [ ] 단일 해 상한 — 8×8 단일 해 경우의 수 상한 약 3천만, 51+ 확장 시 9×9 검토
- [ ] 후반 이탈 위험 — 8×8 관문(45 · 50) 난이도 완화 여부
